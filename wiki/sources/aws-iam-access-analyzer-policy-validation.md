## Evidence

### `basic-validation-scope`

- **AWS states:** IAM Access Analyzer validates a submitted policy against IAM policy grammar and AWS best practices. Its findings are classified as security warnings, errors, general warnings, and suggestions; AWS presents them as recommendations for writing functional policies that conform to security best practices.
- **Locator:** `Validate policies with IAM Access Analyzer` > opening paragraph; `Validating policies in IAM (console)` > `Security`, `Errors`, `Warnings`, and `Suggestions`

### `console-and-api-coverage`

- **AWS states:** The IAM console shows these findings for managed policies and inline user or role policies, but not for inline group policies. The AWS CLI and API expose validation through `aws accessanalyzer validate-policy` and `ValidatePolicy`.
- **Locator:** `Validating policies in IAM (console)` > opening paragraph; `Validating policies using IAM Access Analyzer (AWS CLI or AWS API)` > `To view findings generated by IAM Access Analyzer policy validation (AWS CLI or AWS API)`

### `new-access-is-an-optional-separate-check`

- **AWS states:** When editing an existing policy, a user can optionally run a custom policy check that compares the update with the existing version and highlights a statement if the modified permissions grant new access. AWS charges for each check for new access.
- **Locator:** `Validating policies in IAM (console)` > paragraph beginning `Optional. If you are editing an existing policy` and the following `Note`

### `validation-does-not-replace-testing`

- **AWS requires:** New or edited policies should be tested thoroughly before they enter a production workflow. The page also says the separate Policy validator reports syntax errors that IAM Access Analyzer does not report.
- **Locator:** `Validating policies in IAM (console)` > `Important` beginning `Test new or edited policies thoroughly`; paragraph beginning `When you are finished, choose Next`

## Source criticism

This page defines basic policy validation as static checks against policy grammar and AWS best practices. It does not claim to prove the effective authorization of every principal and resource in an AWS environment, and AWS explicitly directs users to test policies before production. AWS documents external-access, internal-access, and unused-access analysis as separate IAM Access Analyzer capabilities. The page is mutable under a `latest` URL, and its coverage can change after retrieval.
