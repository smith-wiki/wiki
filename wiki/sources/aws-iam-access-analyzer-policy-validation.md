## Overview

This IAM User Guide page explains how IAM Access Analyzer validates a single policy document against IAM grammar and AWS best practices, how its findings are graded from security warnings to suggestions, where the console and the CLI or API show them, and the optional, charged check for new access when a policy is edited. It is undated vendor documentation under a mutable latest URL, written for people authoring policies. It presents validation as static checking: it does not claim to establish effective permissions across an account, and AWS itself says to test policies before production. The broader analyzers are described in [Using IAM Access Analyzer](../aws-iam-access-analyzer-overview/).

## Key points

- IAM Access Analyzer validates a submitted policy against IAM policy grammar and AWS best practices. Its findings are classified as security warnings, errors, general warnings, and suggestions; AWS presents them as recommendations for writing functional policies that conform to security best practices. (`Validate policies with IAM Access Analyzer` > opening paragraph; `Validating policies in IAM (console)` > `Security`, `Errors`, `Warnings`, and `Suggestions`)
- The IAM console shows these findings for managed policies and inline user or role policies, but not for inline group policies. The AWS CLI and API expose validation through `aws accessanalyzer validate-policy` and `ValidatePolicy`. (`Validating policies in IAM (console)` > opening paragraph; `Validating policies using IAM Access Analyzer (AWS CLI or AWS API)` > `To view findings generated by IAM Access Analyzer policy validation (AWS CLI or AWS API)`)
- When editing an existing policy, a user can optionally run a custom policy check that compares the update with the existing version and highlights a statement if the modified permissions grant new access. AWS charges for each check for new access. (`Validating policies in IAM (console)` > paragraph beginning `Optional. If you are editing an existing policy` and the following `Note`)
- New or edited policies should be tested thoroughly before they enter a production workflow. The page also says the separate Policy validator reports syntax errors that IAM Access Analyzer does not report. (`Validating policies in IAM (console)` > `Important` beginning `Test new or edited policies thoroughly`; paragraph beginning `When you are finished, choose Next`)
