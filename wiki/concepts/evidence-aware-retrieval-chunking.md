## What it means

A retrieval *chunk* is a searchable view of a source passage, not the passage's authority. Keep an immutable document version and character or byte offsets for each text span; for a PDF, retain page and layout coordinates; for code, retain commit, path, symbol, and lines. This builds on [web capture fidelity](../web-capture-fidelity/) and [scientific PDF structure extraction](../scientific-pdf-structure-extraction/): no chunker can restore a table, caption, code block, or reading order that the parser already discarded. [Visual evidence retrieval](../visual-evidence-retrieval/) remains separate for figures that text cannot represent.

Three decisions are often mislabeled as one competition:

| Layer | Candidate | Actual intervention |
| --- | --- | --- |
| **Boundaries** | Recursive or structure-aware | Follow headings, paragraphs, separators, and hard size limits; preserve code functions, PDF sections/tables, and web heading or DOM scope where the captured structure permits it. |
| **Boundaries** | Sentence grouping | Segment into sentences, then group neighboring sentences under a token budget; a sentence alone may be too short to stand independently. |
| **Boundaries** | Semantic | Find embedding-distance breakpoints or cluster neighboring sentences; algorithm and chunk-size constraints materially vary. |
| **Boundaries** | Neural | Chonkie `NeuralChunker` predicts separators with a token classifier; this is not a retrieval-trained model in the cited implementation. |
| **Boundaries** | LLM-driven | Chonkie `SlumberChunker` asks a Genie to select a split among recursively generated candidate passages; it emits original text, not a source rewrite. |
| **Representation** | Late chunking | Choose boundaries first, encode a larger document window, then pool contextual token states within each span. |
| **Representation/indexing** | Contextual Retrieval | Generate and prepend a chunk-specific document-aware text prefix before embedding and BM25 indexing; optional reranking is yet another layer. |

Chonkie's pinned implementation and documentation disagree on some defaults; fix versions and parameters before testing ([Chonkie contributors, n.d.](../../sources/chonkie-chunkers-repository/)). Late chunking needs a long-context embedding model and cannot carry full context across arbitrarily long documents; generated prefixes add index-time model calls and require a source-fidelity audit ([Guenther et al., 2025](../../sources/jina-late-chunking-study/); [Ford, 2024](../../sources/anthropic-contextual-retrieval/)).

## What published evaluations actually establish

Chroma's main top-five table gives **89.5% evidence recall / 3.6% IoU** for recursive 400/0, **88.1% / 6.9%** for recursive 200/0, **91.3% / 4.5%** for cluster 400/0, and **91.9% / 3.9%** for its GPT-4o splitter. These are synthetic-query excerpt scores with unequal retrieved token volumes, not answer accuracy; its appendix gives conflicting cluster/LLM aggregates and its GPT-4o method is **not** SlumberChunker. The alternative embedder changes the recall leader ([Smith and Troynikov, 2024](../../sources/chroma-chunking-study/)). Qu, Bao, and Tu find fixed sentence grouping wins all four unstitched document-retrieval datasets and three of five evidence datasets; semantic breakpoints especially help artificially stitched, multi-topic documents. Their paper does not directly measure computation cost ([Qu et al., 2024](../../sources/qu-semantic-chunking-study/)). Neither establishes the winner on extracted scientific PDFs or repositories.

For the *same* boundaries, Jina reports mean BEIR **document** nDCG@10 of **52.2 to 54.0** for naive versus late fixed-size embeddings, **52.4 to 54.3** for five-sentence boundaries, across three models and four datasets; some individual cases tie or reverse ([Guenther et al., 2025](../../sources/jina-late-chunking-study/)). Anthropic reports top-20 failure **5.7% to 3.7%** with generated contextual embedding, **to 2.9%** with contextual BM25, **to 1.9%** with a separate reranker, averaging its best embedding setup over codebases, fiction, and papers. Those are **relative failure reductions** of 35%, 49%, and 67% versus the same reference, not percentage-point recall gains. The appendix gives example code passages but not a full reusable benchmark ([Ford, 2024](../../sources/anthropic-contextual-retrieval/); [Anthropic, n.d.](../../sources/anthropic-contextual-appendix/)). Chonkie publishes no comparable NeuralChunker/SlumberChunker passage-retrieval evaluation in the captured repository ([Chonkie contributors, n.d.](../../sources/chonkie-chunkers-repository/)). Do not rank these incompatible metrics against one another: [the apparent winner depends on evidence unit and budget](../../notes/chunking-winners-depend-on-evidence-unit-and-budget/).

## Evaluate on this corpus

**Inference:** Start with a recursive, structure-respecting baseline and a sentence-group baseline with measured token sizes and modest or zero overlap. Use exact path/heading/symbol metadata and a fixed BM25+dense setup for every arm, rather than treating missing document identity as a boundary problem. Add semantic, neural, and Slumber boundaries only when they beat that baseline on held-out evidence at acceptable indexing cost. Test late pooling and generated prefixes as *separate representation factors on identical boundaries*; if comparing a combined system, state its extra lexical, reranking, and token costs ([Smith and Troynikov, 2024](../../sources/chroma-chunking-study/); [Qu et al., 2024](../../sources/qu-semantic-chunking-study/); [Guenther et al., 2025](../../sources/jina-late-chunking-study/); [Ford, 2024](../../sources/anthropic-contextual-retrieval/)).

1. Freeze web captures, original PDFs and extraction version, and repository commits. Collect real information-need queries per stratum (web prose/technical pages, paper narrative/tables/formulas, code/prose/config). Label **all sufficient source passage spans** with document version, offsets, PDF page/box or code path/lines; mark alternative versus jointly required spans. Pool candidate passages from lexical and dense searches and all boundary arms for blind human adjudication, so a single chunker's output does not define the gold. Audit whether the parser retained each gold span before assigning retrieval blame.
2. Split tuning and evaluation by document or near-duplicate family; keep one query set, normalized corpus, tokenizer, embedder/version, retrieval index settings, and lexical fusion constant. Tune chunk size and overlap on development queries and freeze the selected settings for held-out evaluation. Compare roughly matched realized chunk sizes, not just nominal maxima.
3. Map retrieved chunks back to original offsets. At fixed packed context-token budgets, report **complete-evidence hit rate** (all required spans reached, allowing alternatives), unique gold-span coverage, and evidence-token precision with duplicate overlap billed; also report hit/coverage at top 1/5/10/20 with actual retrieved tokens. Use graded nDCG only where candidate passages are independently judged; report document retrieval separately from passage localization. Compare paired query deltas and uncertainty intervals within each source stratum, then a clearly labeled macro average. Include anaphora, exact symbols, boilerplate, tables, caption attachment, very long documents, and isolated needles as failure slices.
4. Measure ingestion wall time, model/API tokens and calls, peak memory, chunk count/index bytes, search and rerank latency, and source/prefix factuality. Plot evidence quality against equal prompt-token budgets and index/query costs. The winner is a measured point on this corpus's quality-cost frontier, not a method name inferred from incompatible published leaderboards.
